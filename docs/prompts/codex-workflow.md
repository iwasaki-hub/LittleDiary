# Codexへの依頼・作業フロー

1. 目的・対象・対象外・保護する設定・完了条件を依頼文に書く。
2. AGENTSと既存工程記録を読み、git status、ブランチ、依存PRを確認する。前提PR未マージならユーザー指定に従って停止し、自動マージしない。
3. クリーンな最新mainから専用ブランチを作成する。破壊的な変更は先に復元可能なタグを作り、上書きしない。
4. Expoのmajorをpackage.jsonで確認し、対応する公式資料を読む。既存APIの記憶だけで実装しない。
5. 最小変更を実施し、ユーザー変更と既存docs・Expo連携情報を保護する。
6. TypeScript・Lint・Doctor・Webビルド・差分を確認。実行済み／未確認、事実／推測、既存／新規エラーを分けて記録する。
7. [工程テンプレート](../development/templates/phase-template.md)を参考に、変更・理由・代替案・復元・再利用知見を記録する。
8. 対象ファイルだけコミットしPRを作成。承認と明示的なマージ指示を待つ。承認後はhead SHA・チェック・競合を再照合してSquash mergeし、mainをff-only同期する。

秘密情報をソース・記録・チャットに保存しない。ログインはユーザーが行う。iPhone実機確認はユーザー報告がある場合のみ成功扱い。UI機能やデプロイを工程の範囲外で開始しない。

## 依頼テンプレート
目的／開始条件／作業ブランチ／保護対象／変更対象／禁止事項／検証コマンド／記録先／コミット・PR名／マージ条件を明示する。

既存の[ホームUI依頼原文](../development/prompts/phase-02-home-ui-codex.md)は移動せず履歴資料として維持する。一般フローは本ファイル、工程固有の過去指示はdevelopment/promptsを参照し、重複して更新しない。
