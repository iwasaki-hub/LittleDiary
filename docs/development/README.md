# LittleDiary 開発記録・再利用ガイド

目的: LittleDiary の「要求→設計→実装→検証→振り返り」を継続的に記録し、別プロジェクトでも使える開発手順を育てる。

## ディレクトリ
- `phases/`: プロジェクト固有の各工程の実施記録（実行前は計画、完了後に結果を追記）
- `prompts/`: Codex に与えたプロンプトの原文。再実行可能な状態に保つ
- `decisions/`: 技術選定や設計変更の理由・代替案
- `templates/`: 他のプロジェクトにもコピーできる汎用記録テンプレート

## 記録ルール
1. 変更前に目的・対象ファイル・受け入れ条件・リスクを明確にする。
2. 1工程1ブランチを原則とし、関係ないファイルは変更しない。
3. Codex が作業したら、変更ファイル・コマンド・結果・未検証項目を `phases/` に追記する。
4. 「実施したこと」「確認済み」「未確認」「次の改善」を区別し、実施していないテストを成功と記録しない。
5. 意思決定の根拠を `decisions/` に残す。バージョン、日付、参照URLも記録する。
6. 汎用化できる学びはテンプレートやチェックリストに還元する。APIキー、個人情報、秘密情報は記録しない。
7. 画面のスクリーンショットを添える場合は個人情報を除去する。
8. マージ前に差分レビューとiPhoneでの実機確認を行う。実機結果はユーザーが確認後に追記する。

## 推奨サイクル
計画 → Codexへ指示 → 実装 → `npx tsc --noEmit` / `npx expo lint` → 実機検証 → 記録更新 → PRレビュー → マージ

## 他プロジェクトへの転用
`templates/phase-template.md` をコピーし、プロジェクト固有の名前、要件、コマンド、検証環境だけ変更する。
実装プロンプトの「役割・制約・成果物・完了報告」構造は他のリポジトリでも使用可能。
